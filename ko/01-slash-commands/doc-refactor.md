# 문서 리팩터링

프로젝트 유형에 맞춰 프로젝트 문서 구조를 리팩터링합니다.

1. **프로젝트 분석**: 유형(라이브러리/API/웹 앱/CLI/마이크로서비스), 아키텍처, 사용자 페르소나를 파악합니다
2. **문서 한곳에 모으기**: 기술 문서를 `docs/`로 옮기고 상호 참조를 제대로 연결합니다
3. **루트 README.md**: 개요, 빠른 시작, 모듈/컴포넌트 요약, 라이선스, 연락처를 담은 진입점으로 간결하게 정리합니다
4. **컴포넌트 문서**: 모듈/패키지/서비스 단위 README 파일을 추가하고 설정과 테스트 방법을 적습니다
5. **`docs/` 정리**: 관련 분류별로 나눕니다
   - 아키텍처, API 레퍼런스, 데이터베이스, 설계, 문제 해결, 배포, 기여 (프로젝트에 맞게 조정)
6. **가이드 작성** (해당하는 것만 선택):
   - 사용자 가이드: 애플리케이션 최종 사용자를 위한 문서
   - API 문서: API의 엔드포인트, 인증, 예시
   - 개발 가이드: 설정, 테스트, 기여 워크플로
   - 배포 가이드: 서비스/앱의 운영 환경 배포
7. **Mermaid 사용**: 모든 다이어그램(아키텍처, 흐름, 스키마)은 Mermaid로 그립니다

문서는 간결하고, 훑어보기 쉽고, 프로젝트 유형에 맞게 유지합니다.
