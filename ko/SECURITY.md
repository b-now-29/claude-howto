# 보안 정책

> **참고:** 이 문서는 [SECURITY.md](../SECURITY.md)의 한국어 번역입니다. 번역과 원문의 해석이 다르면 영어 원문이 우선합니다.

## 개요

Claude How To 프로젝트는 보안을 중요하게 생각합니다. 이 문서는 우리의 보안 관행과, 보안 취약점을 책임 있게 신고하는 방법을 설명합니다.

## 지원 버전

다음 버전에 보안 업데이트를 제공합니다.

| 버전 | 상태 | 지원 기한 |
|---------|--------|---------------|
| 최신 (main) | ✅ 활성 | 현재 + 6개월 |

**참고**: 이 프로젝트는 교육용 가이드이므로, 전통적인 버전별 지원보다 최신 모범 사례와 문서의 보안을 유지하는 데 집중합니다. 업데이트는 main 브랜치에 바로 적용됩니다.

## 보안 관행

### 코드 보안

1. **의존성 관리**
   - 모든 Python 의존성은 `requirements.txt`에 버전을 고정합니다
   - dependabot과 직접 검토로 정기적으로 업데이트합니다
   - 커밋할 때마다 Bandit으로 보안 검사를 합니다
   - pre-commit 훅으로 보안 검사를 합니다

2. **코드 품질**
   - Ruff 린트로 흔한 문제를 잡습니다
   - mypy 타입 검사로 타입 관련 취약점을 막습니다
   - pre-commit 훅으로 기준을 지키게 합니다
   - 모든 변경은 병합 전에 리뷰합니다

3. **접근 제어**
   - `main` 브랜치에 브랜치 보호를 적용합니다
   - 병합 전에 리뷰가 필요합니다
   - 병합 전에 상태 검사를 통과해야 합니다
   - 저장소 쓰기 권한을 제한합니다

### 문서 보안

1. **예제에 비밀 값 넣지 않기**
   - 예제의 모든 API 키는 자리표시자입니다
   - 자격 증명을 코드에 직접 넣지 않습니다
   - `.env.example` 파일로 필요한 변수를 보여 줍니다
   - 비밀 값 관리에 대한 경고를 분명히 적습니다

2. **보안 모범 사례**
   - 예제는 안전한 패턴을 보여 줍니다
   - 문서에서 보안 경고를 눈에 띄게 표시합니다
   - 공식 보안 가이드로 링크합니다
   - 관련 단락에서 자격 증명 다루는 법을 설명합니다

3. **콘텐츠 검토**
   - 모든 문서를 보안 문제 관점에서 검토합니다
   - 기여 지침에 보안 고려 사항을 넣습니다
   - 외부 링크와 참조를 검증합니다

### 의존성 보안

1. **검사**
   - Bandit으로 모든 Python 코드의 취약점을 검사합니다
   - GitHub 보안 알림으로 의존성 취약점을 확인합니다
   - 정기적으로 직접 보안 감사를 합니다

2. **업데이트**
   - 보안 패치는 신속하게 적용합니다
   - 메이저 버전은 신중하게 평가합니다
   - 변경 기록에 보안 관련 업데이트를 적습니다

3. **투명성**
   - 보안 업데이트를 커밋에 기록합니다
   - 취약점 공개는 책임 있게 처리합니다
   - 필요하면 공개 보안 권고를 냅니다

## 취약점 신고

### 신고를 받는 보안 문제

다음과 같은 신고를 환영합니다.
- 스크립트나 예제의 **코드 취약점**
- Python 패키지의 **의존성 취약점**
- 코드 예제의 **암호화 문제**
- 문서에 있는 **인증·인가 결함**
- 설정 예제의 **데이터 노출 위험**
- **인젝션 취약점** (SQL, 명령 등)
- **SSRF/XXE/경로 탐색(path traversal)** 문제

### 범위 밖의 보안 문제

다음은 이 프로젝트의 범위 밖입니다.
- Claude Code 자체의 취약점 (Anthropic에 신고)
- 외부 서비스나 라이브러리의 문제 (해당 업스트림에 신고)
- 사회공학이나 사용자 교육 (이 가이드에는 해당하지 않음)
- 개념 증명(PoC)이 없는 이론상의 취약점
- 공식 채널로 이미 신고된 의존성 취약점

## 신고 방법

### 비공개 신고 (권장)

**민감한 보안 문제는 GitHub의 비공개 취약점 신고 기능을 써 주세요.**

1. 방문: https://github.com/luongnv89/claude-howto/security/advisories
2. "Report a vulnerability"를 클릭합니다
3. 취약점 내용을 입력합니다
4. 다음을 넣습니다.
   - 취약점에 대한 명확한 설명
   - 영향을 받는 부분 (파일, 단락, 예제)
   - 예상되는 영향
   - 재현 단계 (해당하면)
   - 제안하는 수정 방법 (있다면)

**신고 뒤 진행:**
- 48시간 안에 접수를 확인합니다
- 조사하고 심각도를 평가합니다
- 신고자와 함께 수정 방법을 만듭니다
- 공개 일정을 조율합니다
- 보안 권고에 신고자를 밝힙니다 (익명을 원하면 밝히지 않음)

### 공개 신고

민감하지 않거나 이미 공개된 문제는 다음과 같이 신고합니다.

1. `security` 레이블로 **GitHub 이슈를 엽니다**
2. 다음을 넣습니다.
   - 제목: `[SECURITY]` 뒤에 짧은 설명
   - 자세한 설명
   - 영향을 받는 파일이나 단락
   - 예상되는 영향
   - 제안하는 수정 방법

## 취약점 대응 절차

### 평가 (24시간)

1. 신고 접수를 확인합니다
2. [CVSS v3.1](https://www.first.org/cvss/v3.1/specification-document)로 심각도를 평가합니다
3. 범위 안인지 판단합니다
4. 첫 평가 결과를 신고자에게 알립니다

### 수정 (1–7일)

1. 수정 방법을 만듭니다
2. 수정을 리뷰하고 테스트합니다
3. 보안 권고를 작성합니다
4. 릴리스 노트를 준비합니다

### 공개 (심각도에 따라 다름)

**치명 (CVSS 9.0–10.0)**
- 즉시 수정을 배포합니다
- 공개 권고를 냅니다
- 신고자에게 24시간 전에 미리 알립니다

**높음 (CVSS 7.0–8.9)**
- 48–72시간 안에 수정을 배포합니다
- 신고자에게 5일 전에 미리 알립니다
- 배포할 때 공개 권고를 냅니다

**중간 (CVSS 4.0–6.9)**
- 다음 정기 업데이트에 수정을 배포합니다
- 배포할 때 공개 권고를 냅니다

**낮음 (CVSS 0.1–3.9)**
- 다음 정기 업데이트에 수정을 넣습니다
- 배포할 때 권고를 냅니다

### 게시

보안 권고에는 다음을 넣습니다.
- 취약점 설명
- 영향을 받는 부분
- 심각도 평가 (CVSS 점수)
- 수정된 버전
- 임시 해결 방법 (해당하면)
- 신고자 표기 (동의한 경우)

## 신고자를 위한 모범 사례

### 신고하기 전에

- **문제 확인**: 일관되게 재현할 수 있나요?
- **기존 이슈 검색**: 이미 신고되지 않았나요?
- **문서 확인**: 안전한 사용법 안내가 있나요?
- **수정 테스트**: 제안하는 수정이 동작하나요?

### 신고할 때

- **구체적으로**: 정확한 파일 경로와 줄 번호를 알려 줍니다
- **맥락 포함**: 왜 보안 문제인가요?
- **영향 설명**: 공격자가 무엇을 할 수 있나요?
- **단계 제공**: 어떻게 재현하나요?
- **수정 제안**: 어떻게 고치면 될까요?

### 신고한 뒤에

- **기다려 주세요**: 운영 인력이 한정되어 있습니다
- **빠르게 응답해 주세요**: 추가 질문에 신속히 답해 주세요
- **비밀을 지켜 주세요**: 수정 전에는 공개하지 않습니다
- **조율을 존중해 주세요**: 공개 일정은 우리 일정을 따릅니다

## 보안 헤더와 설정

### 저장소 보안

- **브랜치 보호**: main 브랜치 변경에는 승인 2개가 필요합니다
- **상태 검사**: 모든 CI/CD 검사를 통과해야 합니다
- **CODEOWNERS**: 주요 파일에 지정된 리뷰어가 있습니다
- **서명된 커밋**: 기여자에게 권장합니다

### 개발 보안

```bash
# pre-commit 훅 설치
pre-commit install

# 로컬에서 보안 검사 실행
bandit -c pyproject.toml -r scripts/
mypy scripts/ --ignore-missing-imports
ruff check scripts/
```

### 의존성 보안

```bash
# 알려진 취약점 확인
pip install safety
safety check

# 또는 pip-audit 사용
pip install pip-audit
pip-audit
```

## 기여자를 위한 보안 지침

### 예제를 작성할 때

1. **비밀 값을 코드에 직접 넣지 않습니다**
   ```python
   # ❌ 나쁜 예
   api_key = "sk-1234567890"

   # ✅ 좋은 예
   api_key = os.getenv("API_KEY")
   ```

2. **보안상 영향을 알립니다**
   ```markdown
   ⚠️ **보안 참고**: `.env` 파일은 절대 git에 커밋하지 않습니다.
   바로 `.gitignore`에 추가합니다.
   ```

3. **안전한 기본값을 씁니다**
   - 인증을 기본으로 켭니다
   - 가능한 곳에서는 HTTPS를 씁니다
   - 입력을 검증하고 정제합니다
   - 매개변수화된 쿼리를 씁니다

4. **보안 고려 사항을 문서에 적습니다**
   - 보안이 왜 중요한지 설명합니다
   - 안전한 패턴과 위험한 패턴을 비교해 보여 줍니다
   - 신뢰할 수 있는 출처로 링크합니다
   - 경고를 눈에 띄게 넣습니다

### 기여를 리뷰할 때

1. **노출된 비밀 값 확인**
   - 흔한 패턴(api_key=, password=)을 찾아봅니다
   - 설정 파일을 검토합니다
   - 환경 변수를 확인합니다

2. **안전한 코딩 관행 확인**
   - 코드에 직접 넣은 자격 증명이 없는지
   - 입력 검증이 알맞은지
   - 인증·인가가 안전한지
   - 파일을 안전하게 다루는지

3. **보안상 영향 테스트**
   - 악용될 수 있나요?
   - 최악의 경우는 무엇인가요?
   - 경계 사례가 있나요?
