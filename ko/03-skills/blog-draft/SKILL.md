## 사용자 입력

```text
$ARGUMENTS
```

진행하기 전에 사용자 입력을 **반드시** 고려해야 합니다. 사용자는 다음을 제공해야 합니다.
- **아이디어/주제**: 블로그 글의 핵심 개념이나 주제
- **자료**: 조사할 URL, 파일, 참고 자료 (선택이지만 권장)
- **대상 독자**: 블로그 글을 읽을 사람 (선택)
- **어조/스타일**: 격식체, 편한 말투, 기술적인 글 등 (선택)

**중요**: 사용자가 **이미 있는 블로그 글**의 수정을 요청하면 0~8단계를 건너뛰고 바로 **9단계**부터 시작합니다. 먼저 기존 초안 파일을 읽은 뒤 반복 과정을 진행합니다.

## 실행 흐름

다음 단계를 순서대로 따릅니다. **단계를 건너뛰거나, 표시된 곳에서 사용자 승인 없이 진행하지 마세요.**

### 0단계: 프로젝트 폴더 만들기

1. `YYYY-MM-DD-short-topic-name` 형식으로 폴더 이름을 만듭니다
   - 오늘 날짜를 씁니다
   - 주제로 짧고 URL에 쓰기 좋은 슬러그를 만듭니다 (소문자, 하이픈, 최대 5단어)

2. 폴더 구조를 만듭니다:
   ```text
   blog-posts/
   └── YYYY-MM-DD-short-topic-name/
       └── resources/
   ```

3. 진행하기 전에 사용자와 폴더 생성을 확인합니다.

### 1단계: 조사와 자료 수집

1. 블로그 글 디렉터리에 `resources/` 하위 폴더를 만듭니다

2. 제공된 자료마다:
   - **URL**: 내용을 가져와 핵심 정보를 `resources/`에 markdown 파일로 저장합니다
   - **파일**: 읽고 요약해 `resources/`에 저장합니다
   - **주제**: 웹 검색으로 최신 정보를 모읍니다

3. 자료마다 `resources/`에 요약 파일을 만듭니다:
   - `resources/source-1-[short-name].md`
   - `resources/source-2-[short-name].md`
   - 등

4. 각 요약에는 다음을 넣습니다:
   ```markdown
   # 출처: [제목/URL]

   ## 핵심 내용
   - 내용 1
   - 내용 2

   ## 관련 인용/데이터
   - 인용 또는 통계 1
   - 인용 또는 통계 2

   ## 주제와의 관계
   관련성에 대한 짧은 설명
   ```

5. 사용자에게 조사 요약을 보여 줍니다.

### 2단계: 브레인스토밍과 확인

1. 아이디어와 조사한 자료를 바탕으로 다음을 보여 줍니다:
   - 조사에서 찾은 **주요 주제**
   - 블로그 글의 **가능한 관점**
   - 다뤄야 할 **핵심 내용**
   - 확인이 필요한 정보의 **빈틈**

2. 확인 질문을 합니다:
   - 독자가 가장 기억하길 바라는 점은 무엇인가요?
   - 조사 내용 중 특히 강조하고 싶은 부분이 있나요?
   - 목표 길이는 얼마인가요? (짧게: 500~800단어, 중간: 1000~1500, 길게: 2000 이상)
   - 빼고 싶은 내용이 있나요?

3. **사용자의 답을 받기 전에는 진행하지 않습니다.**

### 3단계: 개요 제안하기

1. 다음을 포함한 구조화된 개요를 만듭니다:

   ```markdown
   # 블로그 글 개요: [제목]

   ## 메타 정보
   - **대상 독자**: [누구]
   - **어조**: [스타일]
   - **목표 길이**: [단어 수]
   - **핵심 메시지**: [전달할 내용]

   ## 제안 구조

   ### 도입/훅
   - 시작 훅 아이디어
   - 배경 설명
   - 핵심 주장

   ### 단락 1: [제목]
   - 핵심 내용 A
   - 핵심 내용 B
   - [출처]의 근거

   ### 단락 2: [제목]
   - 핵심 내용 A
   - 핵심 내용 B

   [모든 단락에 대해 계속...]

   ### 결론
   - 핵심 내용 요약
   - 행동 유도 또는 마무리 생각

   ## 인용할 출처
   - 출처 1
   - 출처 2
   ```

2. 사용자에게 개요를 보여 주고 **승인이나 수정을 요청합니다**.

### 4단계: 승인된 개요 저장하기

1. 사용자가 개요를 승인하면 블로그 글 폴더에 `OUTLINE.md`로 저장합니다.

2. 개요가 저장되었는지 확인합니다.

### 5단계: 개요 커밋하기 (git 저장소인 경우)

1. 현재 디렉터리가 git 저장소인지 확인합니다.

2. 그렇다면:
   - 새 파일을 스테이징합니다: 블로그 글 폴더, resources, OUTLINE.md
   - 다음 메시지로 커밋합니다: `docs: Add outline for blog post - [topic-name]`
   - 원격으로 푸시합니다

3. git 저장소가 아니면 이 단계를 건너뛰고 사용자에게 알립니다.

### 6단계: 초안 쓰기

1. 승인된 개요를 바탕으로 블로그 글 전체 초안을 씁니다.

2. OUTLINE.md의 구조를 정확히 따릅니다.

3. 다음을 넣습니다:
   - 훅이 있는 흥미로운 도입부
   - 명확한 단락 제목
   - 조사에서 얻은 근거와 예시
   - 단락 사이의 자연스러운 연결
   - 핵심 메시지가 담긴 강한 결론
   - **인용**: 모든 비교, 통계, 데이터, 사실 주장은 **반드시** 원래 출처를 밝혀야 합니다

4. 초안을 블로그 글 폴더에 `draft-v0.1.md`로 저장합니다.

5. 형식:
   ```markdown
   # [블로그 글 제목]

   *[선택: 부제나 태그라인]*

   [본문 인용이 포함된 전체 내용...]

   ---

   ## 참고 문헌
   - [1] 출처 1 제목 - URL 또는 인용
   - [2] 출처 2 제목 - URL 또는 인용
   - [3] 출처 3 제목 - URL 또는 인용
   ```

6. **인용 요구 사항**:
   - 모든 데이터, 통계, 비교에는 **반드시** 본문 인용이 있어야 합니다
   - [1], [2] 같은 번호 참조나 [출처 이름] 같은 이름 인용을 씁니다
   - 인용은 끝의 참고 문헌 단락과 연결합니다
   - 예: "연구에 따르면 개발자의 65%가 TypeScript를 선호합니다 [1]"
   - 예: "React는 렌더링 속도에서 Vue보다 20% 빠릅니다 [React Benchmarks 2024]"

### 7단계: 초안 커밋하기 (git 저장소인 경우)

1. git 저장소인지 확인합니다.

2. 그렇다면:
   - 초안 파일을 스테이징합니다
   - 다음 메시지로 커밋합니다: `docs: Add draft v0.1 for blog post - [topic-name]`
   - 원격으로 푸시합니다

3. git 저장소가 아니면 건너뛰고 사용자에게 알립니다.

### 8단계: 검토를 위해 초안 보여 주기

1. 사용자에게 초안 내용을 보여 줍니다.

2. 피드백을 요청합니다:
   - 전체적인 인상은 어떤가요?
   - 늘리거나 줄일 단락이 있나요?
   - 어조를 조정해야 하나요?
   - 빠진 정보가 있나요?
   - 구체적으로 고치거나 다시 쓸 부분이 있나요?

3. **사용자의 답을 기다립니다.**

### 9단계: 반복하거나 마무리하기

**사용자가 변경을 요청하면:**
1. 요청된 수정 사항을 모두 기록합니다
2. 다음을 조정해 6단계로 돌아갑니다:
   - 버전 번호를 올립니다 (v0.2, v0.3 등)
   - 모든 피드백을 반영합니다
   - `draft-v[X.Y].md`로 저장합니다
   - 7~8단계를 반복합니다

**사용자가 승인하면:**
1. 최종 초안 버전을 확인합니다
2. 사용자가 원하면 `final.md`로 이름을 바꿉니다
3. 블로그 글 작성 과정을 요약합니다:
   - 만든 버전 수
   - 버전 사이의 주요 변경
   - 최종 단어 수
   - 만든 파일

## 버전 추적

모든 초안은 버전 번호를 올려 가며 보존합니다.
- `draft-v0.1.md` - 첫 초안
- `draft-v0.2.md` - 첫 번째 피드백 반영 후
- `draft-v0.3.md` - 두 번째 피드백 반영 후
- 등

그래서 블로그 글이 어떻게 발전했는지 추적하고, 필요하면 되돌릴 수 있습니다.

## 출력 파일 구조

```text
blog-posts/
└── YYYY-MM-DD-topic-name/
    ├── resources/
    │   ├── source-1-name.md
    │   ├── source-2-name.md
    │   └── ...
    ├── OUTLINE.md
    ├── draft-v0.1.md
    ├── draft-v0.2.md (반복한 경우)
    └── draft-v0.3.md (더 반복한 경우)
```

## 품질을 높이는 팁

- **훅**: 질문, 놀라운 사실, 공감 가는 상황으로 시작합니다
- **흐름**: 각 문단이 다음 문단과 이어져야 합니다
- **근거**: 조사한 데이터로 주장을 뒷받침합니다
- **인용**: 다음은 **항상** 출처를 밝힙니다:
  - 모든 통계와 데이터 (예: "[출처]에 따르면 75%가...")
  - 제품, 서비스, 접근 방식 사이의 비교 (예: "X는 Y보다 2배 빠릅니다 [출처]")
  - 시장 동향, 연구 결과, 벤치마크에 대한 사실 주장
  - [출처 이름] 또는 [저자, 연도] 형식의 본문 인용을 씁니다
- **목소리**: 처음부터 끝까지 일관된 어조를 유지합니다
- **길이**: 목표 단어 수를 지킵니다
- **가독성**: 짧은 문단과, 알맞은 곳에 글머리 기호를 씁니다
- **행동 유도**: 명확한 행동 유도나 생각할 거리를 주는 질문으로 끝냅니다

## 메모

- 표시된 확인 지점에서는 항상 사용자 승인을 기다립니다
- 기록을 위해 모든 초안 버전을 보존합니다
- URL이 주어지면 최신 정보를 위해 웹 검색을 씁니다
- 자료가 부족하면 사용자에게 더 요청하거나 추가 조사를 제안합니다
- 대상 독자에 맞게 어조를 조정합니다 (기술, 일반, 비즈니스 등)
